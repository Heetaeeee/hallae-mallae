# B — 분배 기능: 부담률·담당자 추천 (박지호)

[공용 명세](README.md)의 데이터 형태와 API 계약을 먼저 읽어주세요.

이 문서는 분배 기능과 B가 담당하는 서버·저장소·배포 작업을 다룹니다.

| 구분 | 담당 |
|---|---|
| 화면 | 부담률 막대, 담당자 추천·배정 패널 — `public/js/load.js` |
| 계산 규칙 | 부담률·추천 — `src/lib/load.js`, 추천 근거 — `src/lib/explain.js` |
| 기능 API | `GET /api/loads`, `POST /api/recommend` |
| 공용 서버 | Express 연결, 저장소, 방 서버 뼈대 |
| 배포 | Docker 실행 환경, 서버 배포·데이터 유지 |

AI 세분화·블라인드 추정은 A, 팀원·작업 관리와 진행률은 C가 담당합니다.

## 역할의 핵심

저장된 팀원·작업 데이터를 기준으로 부담률을 다시 계산하고, 같은 조건에는 같은 순서의 추천 결과를 제공합니다.

추천은 확정 지시가 아니라 팀의 결정을 돕는 참고 자료입니다. 최종 담당자는 팀이 선택합니다.

가능한 시간 0, 동률, 후보 없음, 과부하, 재추천, 상위 작업 제외 같은 조건은 테스트로 검증합니다.

### 저장 형식과 스위치

`ROOMS_ENABLED`는 기본적으로 0 또는 미설정으로 유지합니다.

| 상태 | 저장소 동작 |
|---|---|
| 꺼짐·기존 파일 | 기존 `{ members, tasks }` 형식 유지 |
| 꺼짐·파일 없음 | 조회만으로 파일 생성하지 않음 |
| 켜짐·기존 파일 | 백업 후 방별 구조로 이전 |
| 켜짐·파일 없음 | 새 방별 구조 생성 |
| 이미 이전된 파일 | 스위치를 꺼도 방별 구조 유지 |

기존 형식에서는 저장 없이 기본 방 코드 `LEGACY`를 사용합니다.

`loadRoom('LEGACY')`·`saveRoom('LEGACY', room)`도 기존 형식에 대응하므로, 다른 담당자가 라우터를 미리 전환할 수 있습니다.

기존 형식에는 방 메타데이터를 저장하지 않습니다. 임시 정원은 등록 인원 이상으로 구성합니다.

방별 형식의 기본 방도 정원이 등록 인원보다 작아지지 않도록 보정합니다. 일반 방의 정원은 자동으로 늘리지 않습니다.

이미 이전된 파일을 이전 코드로 읽으려면 백업 복원이 필요합니다. 스위치를 끄는 것만으로 저장 형식이 복원되지는 않습니다.

### B API 방별 전환

[PR #59](https://github.com/Heetaeeee/hallae-mallae/pull/59)에서 main에 반영.

부담률 조회와 담당자 추천은 `loadRoom(req.roomCode)`로 요청에 연결된 방의 데이터만 읽습니다.

`test/room-load-api.test.js`의 통합 테스트 6개로 다음을 확인합니다.

- 같은 팀원 ID라도 방별 작업량과 부담률을 분리
- 방별 작업량에 따른 추천 결과 분리
- 다른 방에만 있는 작업 ID의 추천 요청 거부
- 조회·추천 전후 저장 데이터 보존
- 활성화 상태에서 방 코드 누락·잘못된 형식 거부
- 비활성화 상태에서 헤더와 관계없이 기본 방 사용

라우터와 공용 화면의 방별 전환은 main에 반영됐습니다.
운영 환경은 활성화 전 추가 점검을 마칠 때까지 `ROOMS_ENABLED=0`을 유지합니다.
