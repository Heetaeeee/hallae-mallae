# B — 분배 기능: 부담률 · 담당자 추천 (박지호)

[team/README.md](README.md)의 공용 데이터 형태와 API 형식을 먼저 읽어주세요. 이 문서는 그 위에서 B가 맡을 것만 다룹니다.

| | 맡는 것 |
|---|---|
| **화면** | 부담률 막대, 담당자 추천 · 배정 패널 — `public/js/load.js` |
| **계산 규칙** | 작업 부담률, 담당자 추천 — `src/lib/load.js` · 추천 근거 문장 — `src/lib/explain.js` |
| **서버 API** | `POST /api/recommend` · `GET /api/loads` |
| **공용** | Express 스캐폴드, 저장 `src/lib/store.js`, **방 서버 뼈대** (`src/lib/room.js` · `src/middleware/room-context.js` · `src/routes/rooms.js`) |
| **배포** | Docker 실행 환경, 서버 배포 · 데이터 유지 |

**안 맡는 것:** AI 세분화 · 블라인드 추정(김권섭), 팀원 · 작업 등록과 진행률(우희태)

---

## 이 역할의 핵심 문장

**이 서비스의 이름값인 "공정한 분배"를 계산하는 곳입니다.**

제안 이슈에서 받은 지적이 "ChatGPT에 물어도 되는 것 아니냐"였습니다. 답은 **저장되고, 자동으로 다시 계산되고, 항상 같은 결과가 나온다**는 것이고, 그 셋이 B의 코드입니다. 예외(가능한 시간 0, 동률, 후보 없음, 과부하, 재추천, 상위 작업 제외)가 테스트로 박혀 있어야 발표에서 "규칙이 뭔가요"에 바로 답할 수 있습니다.

추천은 확정 지시가 아니라 팀의 결정을 돕는 참고 자료입니다. 최종 담당자는 팀이 선택합니다.

## 입장 코드 서버 뼈대 (#56)

### 구현 범위

- 방 코드 생성 · 입력 검사
- 방 생성 · 조회 · 최초 입장 · 정원 수정 API
- 기존 저장 형식 호환
- 활성화 시 원본 백업 · 방별 저장 구조 이전
- 공용 방 코드 검사와 `req.roomCode` 전달
- 정원 변경으로 최초 공개 조건이 충족될 때 공개 기록 저장
- 설정 조회 API와 기능 스위치
- 팀원 이름 검사 함수(C), 공개 처리 함수(A) 재사용

### 저장 형식과 스위치

`ROOMS_ENABLED` 는 기본적으로 0 또는 미설정으로 둡니다. **전체 전환과 통합 검증이 끝날 때까지 켜지 않습니다.**

| 상태 | 저장소 동작 |
|---|---|
| 꺼짐 · 기존 파일 | 기존 `{ members, tasks }` 형식 유지 |
| 꺼짐 · 파일 없음 | 조회만으로 파일을 만들지 않음 |
| 켜짐 · 기존 파일 | 백업 후 방별 구조로 이전 |
| 켜짐 · 파일 없음 | 새 방별 구조 생성 |
| 이미 이전된 파일 | 스위치를 꺼도 방별 구조 유지 |

- 기존 형식에서는 저장 없이 기본 방 코드 **`LEGACY`** 를 씁니다
- `loadRoom('LEGACY')` · `saveRoom('LEGACY', room)` 도 기존 형식에 대응하므로, **다른 담당자가 라우터를 미리 전환할 수 있습니다**
- 기존 형식에는 방 메타데이터를 저장하지 않습니다. 임시 정원은 등록 인원 이상으로 구성합니다
- 방별 형식의 기본 방도 정원이 등록 인원보다 작아지지 않게 보정합니다. 일반 방의 정원은 자동으로 늘리지 않습니다
- 이미 이전된 파일을 이전 코드로 읽으려면 **백업 복원**이 필요합니다. 스위치를 끄는 것만으로 저장 형식이 되돌아가지 않습니다

### B API 방별 전환

부담률 조회와 담당자 추천은 `loadRoom(req.roomCode)`로 요청에 연결된 방의 데이터만 읽습니다.

`test/room-load-api.test.js`의 통합 테스트 6개로 다음을 확인합니다.

- 같은 팀원 ID라도 방별 작업량과 부담률을 분리
- 방별 작업량에 따른 추천 결과 분리
- 다른 방에만 있는 작업 ID의 추천 요청 거부
- 조회·추천 전후 저장 데이터 보존
- 활성화 상태에서 방 코드 누락·잘못된 형식 거부
- 비활성화 상태에서 헤더와 관계없이 기본 방 사용

전체 담당자의 전환이 완료될 때까지 `ROOMS_ENABLED=0`을 유지합니다.

## 발표에서 시연할 것

새 작업에 [담당자 추천] → 근거 문장과 예상 부담률 → 추천되지 않은 사람에게도 배정할 수 있음을 보여주고 배정 → 막대 변화. 이어서 한 팀원의 가능한 시간을 0으로 바꿔 추천에서 제외되는 것. 동률 처리, 과부하, 상위 작업 제외도 설명합니다.

방 기능은 전체 전환이 끝난 뒤 **서로 다른 두 방의 데이터가 섞이지 않는 장면**을 보여 줍니다.

**받을 질문** — "동률이면요?" · "가능한 시간이 0이면요?" · "100%를 넘으면요?" 에 테스트 이름으로 답합니다.
